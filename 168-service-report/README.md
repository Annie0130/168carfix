# 168 汽車維修中心 — 電子檢測報告系統

客人用車牌+手機末四碼查詢車輛的電子檢測報告,每輛車貼一張固定 QR Code,
掃描就能看到這輛車所有的維修歷史紀錄。店內人員用共用帳密登入後台建立報告。

## 功能(MVP)

- 店內後台:建立車輛、建立檢測報告(業界標準 checklist)
- 每輛車一組固定 QR Code,可下載列印貼在車上
- 客人端:輸入車牌+手機末四碼查看該車所有報告
- 報告頁面可列印 / 用瀏覽器「另存為 PDF」

## 部署步驟(跟你之前的專案一樣: GitHub → Vercel)

1. **建立 GitHub repo**,把這個資料夾的內容上傳上去。

2. **到 Vercel 建立新專案**,選擇這個 repo,直接 Import。

3. **接資料庫**:在 Vercel 專案的 Storage 分頁,建立一個 Postgres 資料庫
   (Vercel 現在是透過 Neon 整合提供),連接後 Vercel 會自動把
   `POSTGRES_URL` 等環境變數加進專案。

4. **設定其他環境變數**(Vercel 專案 Settings → Environment Variables):
   - `ADMIN_USERNAME`:店內後台登入帳號,自己設一個
   - `ADMIN_PASSWORD`:店內後台登入密碼,自己設一個(不要用預設值)
   - `SESSION_SECRET`:隨便一串長亂碼(例如用密碼產生器生一組)
   - `NEXT_PUBLIC_BASE_URL`:部署完成拿到網址後回來填,例如
     `https://168-service.vercel.app`(QR Code 會用這個網址產生連結)

5. **初始化資料表**:在本機執行(需要先 `vercel env pull` 把
   `POSTGRES_URL` 抓到本機的 `.env` 檔,或直接把值貼到 `.env`):
   ```bash
   npm install
   npm run db:init
   ```
   這會建立 `vehicles` 和 `reports` 兩張表。

6. 完成後,Vercel 每次你 push 到 GitHub 就會自動重新部署,跟你其他系統一樣。

## 使用方式

1. 登入 `/admin/login`,用共用帳密登入後台。
2. 在後台「新增車輛」,輸入車牌、車主手機、姓名、車型。
3. 建好車輛後,進入該車輛頁面可以**下載 QR Code**,列印出來貼在車上
   (建議貼在遮陽板或手套箱內側,雨天洗車比較不會壞掉)。
4. 每次維修完,在該車輛頁面點「建立新檢測報告」,勾選項目狀態、填寫建議。
5. 客人掃 QR Code → 輸入手機末四碼 → 看到這輛車所有維修紀錄,
   點進單一報告可以列印或存 PDF。

## 之後可以加的功能(這次沒做)

- LINE 官方帳號通知:報告建立後自動推播給客人(你弟弟已經有 LINE OA,
  之後可以串接 LINE Messaging API,做法會跟你的 [[line-ai-bot]] 系統類似)
- 報告加入照片、技師電子簽名、費用明細
- 每個技師獨立登入帳號(目前是全店共用一組密碼)

## 關於 PDF

目前是用瀏覽器內建的「列印 → 另存為 PDF」做下載,不需要額外的伺服器資源,
在手機和電腦上都能用。如果之後想要更精緻的 PDF(例如自動加浮水印、
一鍵批次匯出),要另外接 PDF 產生服務,目前先用這個方式驗證流程順不順。

## 關於安全性

後台目前是「全店共用一組帳密」,做法簡單但安全性較低,
建議密碼設複雜一點、不定期更換。如果之後想要「每個技師自己的帳號」
(報告可以顯示是誰做的),可以再跟我說,是可以再加上去的功能。
